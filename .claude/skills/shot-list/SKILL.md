# 镜头表

## 前置
读取：`script/`、`style_bible.md`、`continuity_ledger.md`。缺风格圣经则先走 style-bible。

## 步骤
1. **拆节拍**：每场列出情绪转折点，每个节拍决定是否需要独立镜头。
2. **镜头 → 生成单元**：先按戏剧需要写**镜头**，再把相邻镜头合并成**生成单元**。规格以 `status.md`「已确认规格」为准（导演提供：单次最短5秒；Seedance 2.0 最长15秒，2.5 最长30秒）。规则：
   - 不单独生成低于5秒的镜头；短镜头与相邻镜头合并成一个单元（多镜头序列）。
   - 单元总时长不超过所选模型上限，建议留 1–2 秒余量。
   - 合并优先选：同一空间、同一人物、情绪连续的镜头；不同影调变体、不同空间的镜头不合并。
   - 在 `shots.json` 里每镜加 `unit` 与 `unit_duration`，并给导演一张「单元表」：单元号、含哪些镜、总时长。
   - 同一份镜头表可以给出 2.0 与 2.5 两套分组方案，由导演选。
3. **逐镜填写**，写入 `shots/shots.json`，字段：
   - `id`（如 S01-03）、`scene`、`duration`
   - `size`（景别）、`camera`（运镜）、`angle`
   - `blocking`（站位与调度：谁在画面哪里、朝向、移动方向）
   - `action`（一句话动作）、`dialogue`、`emotion`
   - `characters`、`props`、`location`、`time_light`
   - `refs`（需要的参考图/首尾帧）
   - `continuity`（与前后镜的衔接：视线方向、道具位置、轴线）
   - `status`（planned / prompted / rendered / approved）
4. 给导演一张**易读的表格摘要**（序号、时长、景别、一句话画面），而不是整个 JSON。
5. 标出风险镜头：多人交互、手部特写、文字/字幕入画、快速打斗、群演，并说明处理建议。

## 电影语言准则
- 每个镜头必须回答：观众此刻该看什么、感受什么。
- 遵守180度轴线与视线匹配；换轴要有理由。
- 节奏：情绪高点前给呼吸镜头；开场建立空间，不急于特写。
- 总时长对照目标时长，给出超/欠量。

关卡C：展示摘要后停下，等导演确认或修改。
